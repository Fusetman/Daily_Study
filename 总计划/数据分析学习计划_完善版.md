## 三、学习与复习方法

### 单主线原则

每个阶段保留一条主线，约 80% 时间用于当前主线，约 20% 用于复习旧技能。主线中的必要前置知识、业务口径与表达随任务引入，不开多门完整课程并行赶进度。进入 Excel、SQL 后，每周保留一次 Python 小任务，具体顺序见 [持续练习路线](Python能力清单与练习路线.md)。复习、作品整理和投递准备都计入总时间，不额外叠加。

### 每天如何确定任务

每次开始时先回忆上次的关键点，查看当前阶段目标和上次记录的薄弱点，再选 **一个可验证的小目标**。按“理解问题 → 独立尝试 → 获取必要提示 → 修正 → 换一个输入验证 → 简短复盘”推进。学习资料和练习题按需要使用，不按预估分钟数切换任务。

- 如果仍不能独立解释或重做，继续补练同一知识点；把卡点带到下一次学习。
- 如果已经能独立完成并通过正常输入、边界输入的验证，按学习状态进入阶段内的下一项任务或做迁移练习，不为凑满时长重复简单题。
- 如果当天精力有限，完成一个明确的小目标并记录实际进度即可；2～3 小时是可用时间参考，不是完成要求，也不以学习时长代替掌握程度。
- 结束前记录实际用时、完成证据、还需提示的部分和下次起点。未完成的任务顺延，不重新编排后续日期。

现有逐日页面中的主题、题目、预计时长与日期仅作候选练习和记录位置；实际教学顺序以阶段目标、当天表现和阶段验收为准。跨越或回补某个预设主题时，成果记在实际学习日期的文件夹，并在记录中注明主题来源。未来默认只维护阶段目标、阶段验收和实际每日记录，不再预先生成固定分钟数的逐日必做清单。

### 分级求助规则

1. 先独立分析 10～15 分钟，写出输入、输出、规则和步骤。
2. 回看自己的笔记或已经学过的课程片段。
3. 查询具体报错、官方文档或可靠资料。
4. 使用 AI 时只请求提示、问题定位或思路检查，不先索要完整答案。
5. 问题解决后关闭参考，重新独立完成一遍。
6. 第二天完成一道相似题，检验是否真正掌握。

对尚未学过的概念，先做必要讲解和小例子，再独立练习；不把“独立尝试”变成无前置知识的猜题。记录求助层级：仅查语法/API、获得思路提示、参考代码。前者可属于独立完成，后两者需要后续新题补充证据。

### 间隔复习

核心知识参考学习后的第 2 天、第 7 天和第 30 天复习，以换题和小任务为主。这些是抽查窗口，不是每个知识点必须完成三轮的额外清单；已在项目中独立使用可计作复习，薄弱点优先。

### 验收门槛

- 统一采用“评分 + 核心任务独立完成”的判定，具体见 [统一验收规则](Python能力清单与练习路线.md)。不再使用未定义的“脱离教程完成率 70%”。
- 80 分及以上且核心门槛通过：进入下一阶段。
- 60～79 分且核心门槛通过：有条件推进，并补练复查；不标为完全通过。
- 低于 60 分或核心门槛未过：用 2～3 次学习针对性补强，再换题验收。

质量优先。阶段日期是检查点，可以根据掌握情况前进或顺延；求职准备节点定期核对。需要压缩时先删减低优先级内容，不跳过 SQL、Excel、数据清洗、指标口径和项目表达。

## 六、阶段详细目标

### 阶段 1：Python 独立编程

同时推进基础补齐与完整解题链路：理解要求、拆解步骤、实现、测试、调试和复盘。知识范围、当前证据和候选迁移任务以 [Python 能力清单与练习路线](Python能力清单与练习路线.md) 为准；未学过的先教，已独立验证的不重讲。

成果：

1. 完成基础诊断，至少在两种结构不同的任务中留下本人独立实现与验证的证据。
2. 完成数据清洗测试：规范文本字段、按业务编号去重、保留异常原因、分组统计和排序、导出并核对条数。具体题目见第 3 周计划与周测，不要求编写类或通过课程认证。
3. 完成销售数据分析程序，输出总销售额、商品平均销售额、最高销售商品、排名、品类汇总和 3 条有数据支持的观察。明确一行代表什么；若一个商品多行，先按商品汇总再排名。总额除以商品数不能称为客单价。
4. 用陌生数据与情境完成阶段验收；仅在同一模板里换数字不足以证明迁移。

### 阶段 2：Excel

从零学习界面、表格规范、排序筛选、去重、文本和日期处理；随后学习 `IF`、`SUMIFS`、`COUNTIFS`、`XLOOKUP`、`INDEX+MATCH`、数据透视表和基础图表。

先补相对/绝对引用、表格对象、数字与文本类型、错误值和基础核对。查找匹配先熟练一种方法，再理解替代方法；先核对本机版本，旧版不支持 `XLOOKUP` 时使用 `INDEX+MATCH`。Power Query 先完成一次可刷新导入，复杂清洗留到 BI 阶段。业务口径从本阶段开始：订单量、销量、销售额、客单价与退款，定义分子、分母、时间范围和数据粒度。

成果：一份可刷新和复查的销售月报，包含原始数据、清洗表、指标表、透视表和图表页。

### 阶段 3：SQL

岗位学习重点是通用 SQL，不与刷题网站的 PostgreSQL 绑定。使用 MySQL 8 作为主要练习环境；真实项目需要时再补 PostgreSQL 语法差异。

依次学习：

1. `SELECT`、`WHERE`、`ORDER BY`、`LIMIT`、去重和空值。
2. 聚合、`GROUP BY`、`HAVING`、日期和文本函数。
3. `INNER JOIN`、`LEFT JOIN`、子查询和 `CASE WHEN`。
4. CTE、窗口函数、排名、累计值、首购和留存计算。
5. 订单、用户、商品、退款和活动等业务题。

成果：约 40～60 道有代表性的有效练习作为练习量参考，不以刷题数验收；保留 SQL 错题集和电商数据库分析报告。必须覆盖单表、聚合、多表、CTE、窗口和日期业务题，能从空白独立作答并验证。先理解主键、表粒度、一对多关系；检查 JOIN 前后条数、未匹配项与金额，避免连接放大指标。留存先练简单版本，复杂连续活跃题后补。

本阶段末把 Excel 月报和 SQL 分析整理成第一份可展示案例，并写简历初稿；基础项目讲解、岗位资格和到岗条件检查从此开始，不等到全部课程结束。

### 阶段 4：Pandas

学习 `Series`、`DataFrame`、CSV/Excel 读取、数据类型、缺失值、重复值、异常值、字符串、日期、`merge`、`groupby`、`pivot_table` 和结果导出。

先按能力清单补虚拟环境、包管理、Notebook 执行顺序与最小 NumPy 基础，随后边用边学。合并时核对键唯一性、匹配率与行数，清洗保留原始数据和处理原因。随 EDA 学均值、中位数、分位数与基础柱状/折线/分布图；Matplotlib/Seaborn 先选一套主写法，不同时背两套 API。

成果：订单数据 EDA Notebook，记录每项清洗规则和处理前后校验结果。

### 阶段 5：统计与首个作品

课程学过但容易遗忘，因此采用“概念含义 + 电商例子 + Python/Excel 实操”的方式，不把大量时间用于背公式。

描述统计和基础图表已在前一阶段使用，本阶段重点是抽样、置信区间、假设检验、效应大小、统计与业务意义，以及随机分组和 A/B Test 基础。基础回归根据时间和岗位需要后补。完善已有 EDA，包含业务问题、数据字典、口径、清洗、分析、图表、结论、建议和局限；不为展示统计而强行做不适合数据的检验。

### 阶段 6：Power BI 与求职启动

学习 Power Query、表关系、日期表、度量值、基础 DAX、同比环比、累计值、页面布局和交互筛选。同步完成一页简历、GitHub 项目首页和 1 分钟/5 分钟项目陈述。

优先一个总览页、正确的表关系和少量核心度量，再扩展页面。复用 Excel/Pandas 项目数据；同一问题的 Notebook 和 Dashboard 是一个项目的不同交付物，不重复算作两个独立项目。投递、面试与 BI 共用每周时间，面试集中时缩减看板美化和高级 DAX。

### 阶段 7～10：业务、项目与求职

围绕真实岗位持续训练：销售下降诊断、转化漏斗、商品结构、留存复购、RFM、活动效果、渠道质量和 A/B Test。接受名称不同但实际包含 SQL、Excel、报表、指标或经营分析的第一段相关实习。

## 八、刷题平台真实数据项目

原始背景（2026-09-20 记录，尚未现场复核）：网站曾供约 60 名同学使用，以学号登录并保存错题；当时记录仓库和数据库后台可访问。下一轮使用预计为 2026 年 12 月底至 2027 年 1 月初，实际访问状态、字段和使用规模待到时核验。

### 2026 年 12 月中旬前必须完成

1. 核对数据表及字段，确认是否记录匿名用户标识、题目标识、答题结果、答题时间、知识点和复习批次。
2. 不在分析数据中直接使用学号；生成不可逆或隔离保存的匿名用户编号。
3. 增加简短的数据使用说明，说明保存内容、用途、匿名统计方式、退出或删除数据的方法。
4. 在公开项目中只使用匿名明细或汇总数据，不公开 Token、连接串、学号、姓名、邮箱和其他身份信息。
5. 用测试账号完成一次从答题、入库、导出到匿名化的全流程测试。

11 月先用一次小范围字段盘点确认是否保留答题事件历史，避免只有“当前错题状态”却计划分析历次学习变化。若需要修改产品采集功能，把它作为单独项目任务评估；本计划不授权生产数据导出或系统修改。该准备占当周复习/项目预算，不额外加一整条开发主线。

公开展示默认使用汇总或模拟样例；简单替换学号不能单独证明明细已匿名。只有当前状态时只做截面分析，没有历史时间与事件就不推算留存或进步；约 60 人且使用集中在考试季时，结论限于该样本与时间段，不强求显著性检验或因果结论。

上学期数据未明确说明分析用途，先检查表结构和模拟记录，不直接作为公开作品集数据。优先在确认数据使用范围后，使用下一轮数据完成正式项目；数据不足启用公开数据替代，不让作品集等到 7 月才发现无法交付。

### 可分析问题

- 每日和每轮复习的活跃人数、答题量和使用高峰。
- 整体、知识点和题目维度的正确率与难度。
- 用户复习频次、错题重做和正确率变化。
- 不同复习批次之间的使用差异。
- 在数据条件允许时分析留存、连续学习和复习效果；不把相关性直接解释为因果。
