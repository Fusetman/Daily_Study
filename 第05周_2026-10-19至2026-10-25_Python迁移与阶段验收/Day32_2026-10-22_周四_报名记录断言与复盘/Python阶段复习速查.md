## 1. 动手前先弄清什么

先写清输入、输出和规则，再组织代码：一行代表什么？哪些字段必需？什么算有效或重复？保留哪条？按什么统计、排序？

常见处理链：读取 → 清洗与校验 → 分类与去重 → 汇总与排序 → 核对与导出。具体顺序服从业务规则。例如“保留第一条有效记录”要求先判断有效，再让它占用编号。

## 2. 读懂容器，再逐层取值

| 类型 | 例子 | 常用操作 |
| --- | --- | --- |
| 列表 | `[8, 3]` | `[0]` 取第一项；`append()` 加一项；`len()` 看数量 |
| 字典 | `{'score': 8}` | `['score']` 按键取值；`in` 判断键；`.items()` 遍历键值对 |
| 元组 | `('A', 2, 4.0)` | 按位置取值；适合表达一条固定结构的结果 |
| 集合 | `{'x', 'y'}` | 判断成员、保存唯一值；不依赖其遍历顺序 |

嵌套取值时，每一步都问“现在得到的是什么类型”：

```python
data = {'items': [{'score': 8}]}
data['items']              # 列表
data['items'][0]           # 字典
data['items'][0]['score']  # 数值 8
```

空列表没有第 0 项；键不存在时直接取值会报 `KeyError`。`row.get('score')` 默认在缺键时返回 `None`，因此单靠它不能区分“缺键”和“值本来就是 None”。

## 3. 分支、循环与返回值

- 同一组 `if / elif / else` 最多执行一个分支；多个独立 `if` 可以分别检查多个字段、收集多个问题。
- `continue`：结束当前这一轮，去处理下一条。若还没记录拒绝原因就跳过，会漏掉这条数据。
- `return`：结束整个函数。放在循环内，可能只处理第一条就返回。
- `print()` 展示结果；`return` 把结果交给调用者。函数没有执行带值的 `return`，结果通常就是 `None`。
- 参数是本次调用传入的数据，函数不要误用外部同名变量。

`None` 和 `[]` 含义取决于函数约定。在已做的读取练习里，前者表示读取失败，后者表示成功读取但没有数据。`if not records` 会把两者都判为假，需要区别时用 `is None`。

## 4. 变量应该在哪里创建

| 保存的内容 | 通常创建位置 | 原因 |
| --- | --- | --- |
| 所有有效记录、已接纳编号、类别累计 | 处理循环外、函数内 | 保留本次调用跨行的信息，每次调用重新开始 |
| 当前行的错误原因、当前行的报告字典 | 每轮循环内 | 每条记录重新收集，避免混入上一条的信息 |

列表保存字典时通常保存的是引用，不会自动复制。把同一个字典放进两个列表，通过其中一个修改它，另一处也能看到变化。

`row.copy()` 创建浅拷贝，足以隔离顶层字段的赋值；内部若还有列表或字典，仍可能共享。报告行号和原因可以保存在外层报告字典，避免混进原始业务字段。

## 5. 清洗、转换与异常

- `.strip()` 去掉字符串两端空白；先确认是字符串，不能直接对 `None` 调用。
- `float('1.5')` 得到数值，但不会自动改变原字典中的字符串字段。
- `float('nan')`、`float('inf')` 可以转换成功，成功转换不代表业务合法；转换后用 `math.isfinite(value)` 判断是否为有限数。
- `0` 与缺失不同；是否允许零、负数，要依据题目规则。
- `bool` 是 `int` 的子类，且可转换为浮点数；业务不接受布尔值时，需要单独判断。
- 捕获预期异常，例如数值转换的 `ValueError`、`TypeError`，不要为了不报错而吞掉所有异常。

报错后先看异常类型、最后定位的行和变量实际类型，再用最小输入复现。`IndexError` 常与位置越界有关，`KeyError` 常与键不存在有关。

## 6. 累计与排序

字典累计的基本写法：

```python
totals[group] = totals.get(group, 0) + value
```

每条记录对对应累计只加一次。`+= value` 已经包含旧值，右侧再加一次旧值会重复累计。条数与金额、时长分别统计，不能混用。

排序前，先确认被排序的每一项是什么结构。例如每项为 `(名称, 条数, 合计)`：

```python
def sort_key(item):
    return (-item[2], item[0])
```

排序键从左向右比较：先按合计降序，再按名称升序。`sorted()` 返回新列表，要保存或返回它；不会自动改变原列表。

## 7. CSV、行号和入口

```python
with open(path, encoding='utf-8', newline='') as file:
    reader = csv.DictReader(file)
    # reader.fieldnames 用于检查表头
```

- 校验方向是“每个必需字段都存在于实际表头”，不应仅因有额外列就拒绝。
- 完全空文件可能没有表头；仅表头文件有字段名，但没有数据行。
- 短行的字段值可能为 `None`，清洗和转换前要考虑它。
- 相对路径通常以启动程序时的工作目录为起点，不一定是脚本所在目录。
- 已做练习用 `enumerate(records, start=2)` 记录表头后的原始记录序号，应在筛选前编号。它假设每条记录占一行；字段含换行时不等于物理文件行号。
- 导出时明确表头和字段顺序；确认读取成功后再打开输出，避免失败时覆盖文件。

```python
if __name__ == '__main__':
    # 在这里调用主流程；导入模块时不执行这部分
    pass
```

## 8. 断言的预期从哪里来

**先依据输入和规则手算，再与程序结果比较。** 不能直接照抄实际输出作为正确答案，也不能一报错就改预期去迁就程序。

```python
assert actual == expected
```

列表、字典、元组都可以比较相等。列表和元组的顺序会影响比较结果；字典比较看键值是否相等。累计小数时可能产生浮点误差，需要近似比较时使用 `math.isclose(actual, expected)`。

小样例优先覆盖正常、边界、无效输入。去重样例可让两条合法候选的数值不同，才能看清保留的是哪条。除了核对数量，还要核对具体记录、原因、原始序号和汇总顺序。

互斥且穷尽的分类应满足：输入条数 = 有效 + 无效 + 重复。汇总合计也应能与有效明细对上；这些核对不能单独证明全部结果正确。

## 9. 销售指标别混口径

- 一行可能是一条商品明细，不一定是一笔订单；先明确数据粒度。
- 一个商品多行时，先按商品累计，再比较商品排名。
- 商品平均销售额：总销售额 ÷ 商品数，商品数按题目定义。
- 客单价：按约定统计范围的销售额 ÷ 订单数，需要能识别订单的数据。
- 观察要有数据支持；对原因的猜测要与已知事实分开。
